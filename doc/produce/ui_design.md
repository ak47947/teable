## 1. 设计理念

### 1.1 核心原则

- **清晰直观**: 用户能够快速理解自动化工作流的逻辑
- **一致性**: 与 Teable 现有 UI 风格保持高度一致
- **容错性**: 配置错误应有清晰的视觉提示
- **高效**: 减少点击次数,支持快速配置
- **美观**: 现代化的视觉风格,提升产品溢价感

### 1.2 用户体验目标

- 用户在 1 分钟内能创建一个简单的自动化
- 用户能一眼看出工作流的执行状态
- 复杂的配置项应有序组织,避免压迫感

## 2. 配色方案

## 4. 核心页面

### 4.1 工作流列表页 (Workflow List)

**设计要点**:
- 顶部保留 Teable 标准面包屑和标题
- 右上角突出 "创建自动化" 按钮
- 工作流以卡片形式展示,包含:
  - 工作流名称和简要描述
  - 启停开关 (Switch)
  - 触发器概览 (图标 + 文字)
  - 动作数量
  - 执行统计 (次数、最近执行时间)
  - 更多操作 (编辑、复制、删除、导出)

### 4.2 可视化编辑器 (Visual Editor)

**设计要点**:
- **全屏画布**: 最大化编辑区域,支持无限缩放平移
- **节点设计**: 
  - 圆角矩形 (Border-radius: 12px)
  - 头部有色块区分类型
  - 支持节点展开/折叠显示详情
  - 错误状态时高亮边框和图标
- **连线设计**: 
  - 贝塞尔曲线连接
  - 支持动画流向 (执行中动态效果)
  - 选中时加粗并变色
- **侧边控制栏**:
  - 节点面板: 展示可用的触发器、条件和动作(支持拖拽)
  - 属性面板: 点击节点后滑出,进行详细参数配置
- **浮动控制**:
  - 左下角: 缩放、自适应视图、小地图
  - 底部中央: 快捷操作(撤销、重做、清空)
  - 右上角: 测试执行、保存

### 4.3 执行历史页 (Execution History)

**设计要点**:
- 数据列表形式呈现
- 状态列使用 StatusBadge (成功=绿, 失败=红, 跳过=灰)
- 点击行右侧滑出详情面板,显示该次执行的详细日志和快照数据

## 5. 组件设计

### 5.1 节点卡片 (NodeCard)

```tsx
<div className="node-card">
  <header className="node-header">
    <Icon className="node-icon" />
    <span className="node-title">当记录创建时</span>
    <StatusIndicator />
  </header>
  <main className="node-body">
    <div className="config-summary">
      <span className="label">目标表:</span>
      <span className="value">任务列表</span>
    </div>
  </main>
</div>
```

### 5.2 属性编辑器 (PropertyEditor)

- 使用垂直分组布局
- 表单元素间距: `space-y-4`
- 配置项标签在上方,下方为输入框/选择框
- 支持搜索的选择器,方便从成百上千个字段中筛选
- 变量选择器: 支持在输入框中通过输入 `@` 或 `{{` 快速唤起

### 5.3 变量标签 (VariableTag)

- 背景色: `#dbeafe` (Blue-100)
- 文字色: `#1e40af` (Blue-800)
- 带有小图标,区分来源(触发器、记录、上一动作)

## 6. 交互动效

### 6.1 节点连接

- 拖拽连线时,悬浮在目标句柄上应有吸附效果和颜色提示
- 连接成功后,线条流向动画播放一次

### 6.2 版面过渡

- 配置面板滑出使用 `ease-in-out` 动画 (Duration: 300ms)
- 节点删除时淡出消失

### 6.3 状态指示

- 执行中: 节点虚线边框由旋转效果,连接线有流水动画
- 执行成功: 节点瞬间闪烁绿色,并显示 Check 图标
- 执行失败: 节点红色抖动,并显示异常图标

---

## 总结

Teable 自动化功能的 UI 设计应体现出其**引擎感**。通过清晰的节点布局、鲜明的色彩区分以及流畅的交互体验,将复杂的逻辑配置过程转化为直观的视觉连线过程。

> 以上规范将作为 Phase 3 - 前端界面开发的实施蓝图。
